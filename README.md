# Stage 6 technical smoke test

Date: 2026-11-13. Purpose: verify an isolated server environment and a minimal, auditable single-cell execution loop. This is a technical pilot, not IPF cohort selection, niche discovery, spatial validation, or experimental authorization.

## Scope

Use the public PBMC3k example derived from 10x Genomics (blood cells, not lung or IPF), obtained as the raw-count H5AD referenced in Scanpy 1.11.5, to test acquisition, raw-count checks, QC, filtering, normalization, variable-gene selection, PCA, neighbors, UMAP, Leiden clustering, saving, and output reloading. Clusters are unannotated technical outputs. Demonstration QC cutoffs must not be reused as predeclared Stage 6 biological criteria.

The original 10x archive URL returned HTTP 403 during `pilot_01`; that failed attempt is retained in `logs/pilot_01.log`. Acquisition instead uses the prepared raw-count H5AD explicitly referenced in the pinned Scanpy 1.11.5 source. The downloaded H5AD is preserved byte-for-byte, and the acquisition record identifies both its actual URL and that source definition. This source change does not alter the technical-only scope.

The test uses Scanpy 1.11.5 in a new virtual environment based on the existing Python 3.10.20 interpreter. This is a small Python interoperability test, not a decision that every subsequent analysis must use Scanpy. Existing R and Conda environments are preserved.

## Execute on the server

From the test root, create the environment once:

```bash
(set -o noclobber; bash setup_environment.sh > logs/setup.log 2>&1)
```

The parent directory and `logs/` must exist before redirecting output. The non-clobbering redirect refuses to overwrite an existing setup log. Setup refuses to overwrite an existing `.venv`. It records resolved package versions in `environment.freeze.txt`, checks package dependencies, and verifies core imports.

Run the pipeline with a unique run identifier, using the existing tmux facility so the job is independent of the SSH chat connection:

```bash
tmux new-session -d -s stage6-smoke-20261113 \
  'cd /home/data/t120631/project/ipf_stage6_smoke_test_20261113 && (set -o noclobber; bash run_server.sh pilot_01 > logs/pilot_01.log 2>&1)'
```

Read the saved log and completion record before submitting another run. Use a new run identifier and corresponding log filename for another attempt; an existing log is never truncated by the commands above. The environment setup, input acquisition, and analysis must complete successfully; submission alone is not success. Each analysis verifies the input H5AD hash against `acquisition.json` before processing. Output directories are never overwritten. A partially failed acquisition is retained for diagnosis rather than deleted automatically.

## Verification and provenance

- `input/acquisition.json`: actual H5AD URL, pinned Scanpy source definition, acquisition time, downloaded bytes, H5AD hash, and raw dimensions.
- `environment.freeze.txt`: all resolved Python package versions; generated by the successful setup.
- `runs/<run_id>/raw_counts_checkpoint.h5ad`: all input counts before filtering.
- `runs/<run_id>/processed.h5ad`: transformed data, filtered raw-count layer, embeddings, and unannotated clusters.
- `runs/<run_id>/cell_qc_clusters.csv`: cell identifiers, QC metrics, and cluster assignments.
- `runs/<run_id>/qc.png` and `umap.png`: technical diagnostic figures.
- `runs/<run_id>/run_summary.json`: settings, dimensions, versions, elapsed time, peak process memory, and output-reload checks.
- `runs/<run_id>/SUCCESS.json`: written only after the saved-output checks pass, with artifact hashes.

Keep large inputs and H5AD analysis objects on the server. Retrieve small records and figures for local review; verify their hashes against the server completion record. `results/` contains the reviewed small artifacts when a pilot has completed. Resource measurements apply to this small pilot, not to full IPF or spatial datasets.
